# 训练你自己的 voice pack（声音包）——分步配方

本 skill 出厂附带的是 **2023–2025 年计算机科学（CS）顶会最佳论文语料**上
校准的声音包实例，文件是
`skills/paper-orchestrator/references/voice-calibration.md`。

流水线本身与学科无关：七个阶段、检查点、claims 台账、四个确定性脚本都
不随学科改变。**换学科只换声音包**，而且只换这一个文件。下面是把我们实际
走过的流程整理成的可复用配方——按顺序做，不要跳步。

> 一句话原则：声音包校准的是**断言强度与证据距离的对应关系**，不是句子
> 长相。你要蒸馏的是「这个领域的好作者如何分配自信」，不是「他们爱用
> 哪些词」。

---

## 第 0 步：先认清交付物是什么

最终产物是一份**正面声音模型**，不是禁令清单、不是评分表、不是改写规则。
它需要同时服务两个消费者：

- 阶段 4（起草）：给写作一个可模仿的强度刻度；
- 阶段 7（处置）：给审计报告一个判断「这是防御性削弱还是诚实前瞻」的
  校准尺。

因此它必须写成**倾向 + 理由 + 例证 + 变异范围 + 两侧失败模式**，而不是
「不要写 X」的规则条目。

建议把工作目录建在仓库外（例如 `~/voice-pack-work/`），语料原文只读，
不要提交进 skill。

---

## 第 1 步：选语料（6–10 篇，近 2–3 年，类型混合）

目标不是「这个领域最重要的论文」，而是「这个领域**被同行公认为写得好**的
论文」。最佳论文奖、杰出论文奖、会议推荐列表是可靠信号；高引用但不获奖的
论文容易混入写作一般的工作。

硬性要求：

1. **数量 6–10 篇。** 少于 6 篇，你分不清「个人习惯」与「领域倾向」；
   多于 10 篇，蒸馏成本陡增而边际信息递减。我们的实例用了 8 篇。
2. **时间窗口近 2–3 年。** 写作规范会漂移；十年前的范文会把过时套路带进来。
3. **类型必须混合。** 至少覆盖：
   - 方法类（提出新模型/算法/系统）；
   - 分析类（解释现象、理论、实证研究）；
   - 数据集/基准类；
   - 如有可能，加一篇 position / 立场类。
   单一类型的语料会把「方法论文的节奏」误当成「所有论文的节奏」。
4. **记录版本。** 若读的是 arXiv 版而获奖的是会议版，明确标注，因为措辞
   可能有出入。我们的实例中 3/8 篇是 arXiv 版，已在文件头披露。
5. **记录引用边界。** 只摘短句/短语并标注论文编号与章节；这是 fair use
   范围内的评论与教学引用，不要大段复制。

建一张语料表（标题、会议/年份、奖项、类型、版本、本地文件路径），后面
每个原则的例证都要能指回这张表。

---

## 第 2 步：选择性阅读（只读承载「声音」的部分）

不要从头到尾精读八篇论文——你研究的是文风，不是内容。每篇只读四类位置：

1. **摘要**：看作者如何在一段内安排「已测结果 / 机制解释 / 外推」的强度
   梯度，尤其看数字句是否加 hedge。
2. **引言的主张框定**：看贡献如何被陈述、优先权如何被礼貌地声明、局限
   如何被提前安放。
3. **结果叙述**：看作者如何描述提升、失败案例、消融与意外发现；注意
   “suggests / indicates / we believe” 出现在什么证据距离上。
4. **讨论 + 局限 + 结论**：看作者如何把没做到的事说具体、如何在承认边界
   之后重新锚定贡献、结论是否回到实际展示的层面。

阅读时只做两件事：

- 摘**短引文**（一句或一个短语），标注论文编号与章节；
- 在旁边写一句「这里为什么可信/为什么膨胀/为什么防御」的即时判断。

不要在这一步就总结原则。先攒 40–80 条带上下文的观察，再归纳。

---

## 第 3 步：蒸馏契约（5–8 条原则，缺一不可）

把观察压缩成 **5–8 条倾向**。我们的实例是 8 条。每条必须包含以下五件套，
少一件就不算完成：

1. **倾向（tendency）**：一句可检验的陈述，例如「断言强度随离证据的距离
   衰减，而不随句子位置或重要性衰减」。
2. **WHY**：为什么这样写有效。没有 WHY 的原则会退化成句型模仿。
3. **≥2–3 个语料例证**：来自不同论文的短引文，标注编号与章节。例证要覆盖
   不同位置（摘要、结果、结论），避免只从一篇论文取样。
4. **变异范围（variation range）**：同一倾向在不同论文/类型中的合法变体。
   例如强度分级可以靠词汇、动词（verify / explain / shed light on）或范围
   副词（initially, often）实现，不限于一种手段。
5. **两侧失败模式（both failure modes）**：每条原则必须同时写出
   - **防御侧**：把已确立的说弱、说空（给已测数字加缓冲、把贡献藏进
     「可能有用」）；
   - **膨胀侧**：把未确立的说强、说满（两步外推用测量语气、小效应配大
     形容词）。
   只写一侧，声音包就会把写作推向另一个极端。

另外两条结构要求：

- **必须有一条「刻度尺核心」**：把「断言强度 = 离证据的距离」写成总纲，
  并给出两条铁律——已测结果永不 hedge；两步外的推理永不用测量语气。
- **每条原则的例证总数要够**：单篇论文只能贡献一个例子的模式，一律降级为
  「变异」，不能升格为原则。

写完自查：删掉任何一条原则，会不会让「防御 vs 膨胀」的判断失去依据？
如果不会，这条原则可能只是文风偏好，删掉或并入其他条。

---

## 第 4 步：强制加入「这不是什么」反模板声明

这一节不是可选装饰，是**防空转与防过拟合的安全阀**。必须明确写出：

- **这不是句型模板**：不得把例证改写成可套用的句式；
- **这不是 hedge 配额**：不规定每段/每句要用多少 may/could，也不惩罚
  正常使用 limitations / suggest / indicate；
- **这不是表面光洁度标准**：不是把句子磨圆、把语气统一；
- **这不是结构规则**：不规定段落顺序、章节长度、连接词；
- **单篇论文的模式降级为变异**：只在一篇里出现的写法是「该作者的选择」，
  不是领域倾向；
- **语料自己的反例要保留**：如果语料里存在看似「不合格」但确实有效的
  写法（例如强断言、直白动词），把它写进反模板节，防止校准把好写法误杀。

一个实用的检验：把这一节给一个没读过语料的人看，他应该能明白
「这份文件不是让我照着造句」。

---

## 第 5 步：加入「按类型变异」一节

不同贡献类型的论文，声音重心不同。至少分别描述：

- **方法类**：贡献在机制与实测提升，摘要和结果段可以最直；
- **分析类**：贡献在解释与证据链，推一步/推两步的强度分级更频繁；
- **数据集/基准类**：贡献在覆盖度、质量控制与可复现性，统计叙述多、
  hedge 少；
- **position / 立场类**（如有）：论证结构优先，强度靠论证链而非数字。

关键句是「**跟随贡献实际是什么，而不是跟随论文标签**」：一篇自称方法的
论文如果实际贡献是分析，声音应随实际贡献走。类型变异节要说明哪些差异是
合法的、哪些只是单篇习惯。

---

## 第 6 步：对抗验证（A/B/C 三组，全过才算完成）

声音包写完后，必须做对抗测试——**不能只由写它的人「读一遍觉得对」**。
把测试用例写成可复跑的清单（我们的实例放在
`tests/test_voice_calibration_adversarial.py`，共三组 + 文档一致性检查）。

### A 组：不误伤诚实的前瞻性文字（friendly-fire）

构造若干**完全合规**的段落，覆盖：

- 已测结果的直陈句（带数字、无 hedge）；
- 机制解释（推一步，用 may/suggests）；
- 诚实的下一步计划（“we will verify X on Y next”）；
- 数据集统计的平直叙述（不因没有 hedge 而被判为过度自信）；
- 局限段的具体交代。

判定：这些段落必须全部被判为 **CORRECT**。**通过标准：false flags = 0。**
任何一条被误判为「防御」或「膨胀」，都要改声音包或改判定逻辑，不能改
测试用例来迁就。

### B 组：不同类型论文的节奏可证明地分化

取方法类、分析类、数据集类各一段真实语料风格的文字，检查声音包给出的
节奏/强度判断**不是同一个模板**：

- 方法类结果段允许高密度直陈；
- 分析类允许并需要更多分级词汇；
- 数据集类允许统计陈述不配 hedge。

判定：三类的信号分布/判定理由必须能看出差异。**通过标准：不收敛**——
如果三类文字得到一模一样的处置建议，说明声音包退化成了单一模板。

### C 组：该抓的膨胀仍然抓得住

构造明确的 hype / overclaim 段落（把未验证的外推说成结论、把小效应说成
范式转变、把相关性说成因果），检查声音包驱动的审计仍然报出问题。

判定：全部命中。**通过标准：hype 仍被抓住，且审计是 report-only**——
它只报告并给处置方向，不自动改写、不替作者做科学判断。

### 附加一致性检查

- 文档里写的判定标准，与审计脚本/提示词的实际行为不得矛盾；
- 声音包不得引入新的流程规则（阶段、检查点、台账规则不变）；
- 信号词（may / could / potentially / likely）只是**输入**，不是判决；
- 诚实前瞻句不得被当作 hedge 删除，已测结果不得被「润色」柔化。

三项全过 + 一致性无矛盾，才进入第 7 步。

---

## 第 7 步：替换声音包，其他什么都不改

把新文件放回：

```
skills/paper-orchestrator/references/voice-calibration.md
```

除此之外**不改任何东西**：

- 不改 `SKILL.md`；
- 不改七个阶段与检查点；
- 不改 `claims.jsonl` 台账与 L0–L4 刻度；
- 不改 `voice-rules.md` 的裁决规则（它引用声音包，但不复制其内容）；
- 不改四个脚本；
- 不改兄弟 skill。

替换后跑一遍完整测试：

```bash
python -I -m pytest tests/ -q -p no:cacheprovider
```

并把 `tests/test_voice_calibration_adversarial.py` 中针对语料例证的断言
改成你自己的例证（只改测试对**你的**声音包的期望，不放松 A/B/C 的通过
标准）。

- [ ] 6–10 篇，近 2–3 年，类型混合，版本与奖项有记录；
- [ ] 每篇只读四类位置，观察带编号与章节；
- [ ] 5–8 条原则，每条含倾向 + WHY + ≥2–3 例证 + 变异范围 + 两侧失败模式；
- [ ] 有「刻度尺核心」与两条铁律；
- [ ] 有「这不是什么」反模板节，且保留语料反例；
- [ ] 有按类型变异节，写明「跟随实际贡献」；
- [ ] A 组 false flags = 0；B 组节奏可证明分化；C 组 hype 全中；
- [ ] 文档与审计行为无矛盾；
